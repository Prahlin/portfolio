Working Style

Precise, visual, and persistent.

I like tight feedback loops, measured changes, explicit tradeoffs, and interfaces that are rich without becoming noisy.

Principles

The beliefs that shape the code.

Interface clarity is a backend concern.

If validation, pricing, and state are vague, the UI eventually tells on the system.

Documentation is part of delivery.

Logs, release notes, and screenshots make future decisions cheaper and safer.

Taste should survive constraints.

Small screens, store rules, and payment SDKs still deserve polish and rhythm.

Ship the inspectable version.

Strong portfolios make the hard parts visible: failures, revisions, QA, and rationale.

Work from user paths outward.

Start with what the user is trying to do, then build the system that supports it.

Keep the stack honest.

Use proven tools where reliability matters and custom work where the product needs it.
